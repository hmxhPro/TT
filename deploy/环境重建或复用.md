# SOD 环境重建 / 复用指南

> 适用场景:打包的 conda 环境在目标机用不了(glibc 太老 / 驱动是 CUDA 12.x 不匹配 cu130),
> 或目标机已有一个差不多的环境想直接复用。

---

## 0. 先记住三件事

1. **不需要编译。** 默认检测(YOLOE)和训练(ultralytics `model.train()` 子进程)都是纯 Python + torch wheel。
   只有可选的 GroundingDINO / ByteTrack 源码带 C 扩展,但**项目运行时不调用**,无视即可。
2. **torch/torchvision 要按目标机驱动单独装**(requirements.txt 里是注释掉的)。选版本看驱动:

   | 目标机驱动(`nvidia-smi`) | 装哪个 torch | index-url |
   |---|---|---|
   | R580+ (CUDA 13.0) | cu130 | `https://download.pytorch.org/whl/cu130` |
   | R570+ (CUDA 12.8) | cu128 | `https://download.pytorch.org/whl/cu128` |
   | R560+ (CUDA 12.6) | cu126 | `https://download.pytorch.org/whl/cu126` |
   | R550+ (CUDA 12.4) | cu124 | `https://download.pytorch.org/whl/cu124` |
   | R530+ (CUDA 12.1) | cu121 | `https://download.pytorch.org/whl/cu121` |

3. **两个依赖不在 requirements.txt,必须手动补**:`torch torchvision`(见上)、`httpx`(serve_frontend.py 用)。
   另外 `timm` 要 `--no-deps` 装(避免它改写 torch)。

依赖装齐的统一命令(后面会反复用到,记作 **INSTALL_DEPS**):
```bash
PIP=要用的环境的pip路径
$PIP install torch torchvision --index-url https://download.pytorch.org/whl/cu124   # ← 按驱动改 cuXXX
$PIP install -r /路径/backend/requirements.txt
$PIP install --no-deps "timm>=0.9.16"
$PIP install httpx
```

## 场景一:重新创建虚拟环境

### 1A. 在源机重建后重新打包(推荐,目标机继续离线)

```bash
# 源机（需联网）
conda create -n SOD_rebuild python=3.10 -y
conda activate SOD_rebuild

# 装依赖（按上表选 cuXXX）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
pip install -r /home/hmxh/workspace/sodv3/SOD/backend/requirements.txt
pip install --no-deps "timm>=0.9.16"
pip install httpx

# 验证
python -c "import torch,ultralytics,cv2,fastapi,uvicorn,httpx; from ultralytics import YOLO; print(torch.__version__, torch.cuda.is_available())"

# 重新打包，替换总包里的 conda 环境包
pip install conda-pack
conda-pack -n SOD_rebuild \
  -o /home/hmxh/workspace/sodv3/dist/sod-offline-bundle/conda/SOD_env.tar.gz \
  --format tar.gz --n-threads -1 --compress-level 4 --force

# 重新生成单文件总包后照常 scp + install.sh 部署
cd /home/hmxh/workspace/sodv3/dist && tar -cf sod-offline-bundle.tar sod-offline-bundle
```
目标机:正常 `bash install.sh` 即可(它会解包这个新环境)。

### 1B. 在目标机直接用 venv 重建(目标机能联网,或已备好离线 wheel)

```bash
cd /data/sod-offline-bundle
# 解包代码/权重/字体（跳过自带 conda 环境）
tar -xzf app/SOD-app.tar.gz -C .
ln -sfn ../mobileclip_blt.ts backend/weights/mobileclip_blt.ts
mkdir -p .config/Ultralytics && tar -xzf ultralytics/Ultralytics.tar.gz -C .config/Ultralytics
sed "s|__SOD_HOME__|$PWD|g" env.template > backend/.env

# 用系统 Python 3.10 建 venv（脚本固定找 ./env，所以就建在 env/）
python3.10 -m venv env
./env/bin/pip install --upgrade pip
# INSTALL_DEPS（PIP=./env/bin/pip）
./env/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
./env/bin/pip install -r backend/requirements.txt
./env/bin/pip install --no-deps "timm>=0.9.16"
./env/bin/pip install httpx

bash verify.sh
```

> 离线机没网时:先在源机 `pip download -d wheelhouse torch torchvision --index-url .../cuXXX` 和
> `pip download -d wheelhouse -r backend/requirements.txt httpx timm`,把 `wheelhouse/` 拷到目标机,
> 安装时加 `--no-index --find-links wheelhouse`。

## 场景二:复用你用 `conda create` 建的已有环境

适用于:你之前已经用 `conda create` 建好了一个环境(里面有跟显卡 CUDA 匹配的 torch),
想直接拿它跑本项目,不想再解包总包里那个 conda-pack 环境。

> 这种 conda 环境是"原地真实环境",**不需要 `conda-unpack`**(那只针对 conda-pack 解包出来的环境)。

### 第 1 步:找到这个 conda 环境的绝对路径

```bash
conda env list
# 输出示例：
#   base       /home/hmxh/miniconda3
#   myenv  *   /home/hmxh/miniconda3/envs/myenv      ← 这一行最后的路径就是环境目录
```
记下它的路径(下面记作 `CONDA_ENV`,例如 `/home/hmxh/miniconda3/envs/myenv`)。
它的 python / pip 就在 `CONDA_ENV/bin/python`、`CONDA_ENV/bin/pip`。

先确认它满足条件(Python 3.10+ 且 torch 能用 CUDA):
```bash
/home/hmxh/miniconda3/envs/myenv/bin/python -c "import sys,torch; print(sys.version.split()[0], torch.__version__, torch.cuda.is_available())"
# 期望：3.10.x  2.x.x+cuXXX  True
```

### 第 2 步:解包代码/权重/字体(不碰你的 conda 环境)

```bash
cd /data && tar -xf sod-offline-bundle.tar && cd sod-offline-bundle
tar -xzf app/SOD-app.tar.gz -C .
ln -sfn ../mobileclip_blt.ts backend/weights/mobileclip_blt.ts
mkdir -p .config/Ultralytics && tar -xzf ultralytics/Ultralytics.tar.gz -C .config/Ultralytics
sed "s|__SOD_HOME__|$PWD|g" env.template > backend/.env
```

### 第 3 步:把 `env` 软链到你的 conda 环境(关键)

所有部署脚本(`run_backend.sh` / `verify.sh` / `serve_frontend.py`)都固定找 `./env/bin/*`,
所以只要把 `env` 指向你的 conda 环境,**脚本一行都不用改**:

```bash
# 用你第 1 步记下的真实路径替换
ln -sfn /home/hmxh/miniconda3/envs/myenv env
```

### 第 4 步:往这个 conda 环境补齐缺的依赖

```bash
# torch 已有就不会动它；只补缺的。timm 要 --no-deps，httpx 不在 requirements 里要单独装
./env/bin/pip install -r backend/requirements.txt
./env/bin/pip install --no-deps "timm>=0.9.16"
./env/bin/pip install httpx
```

### 第 5 步:自检并启动(和标准部署完全一样)

```bash
bash verify.sh
nohup bash run_backend.sh > backend.out 2>&1 &
nohup ./env/bin/python serve_frontend.py > frontend.out 2>&1 &
# 访问 http://目标IP:8080/
```

> 说明:
> - 因为 `env` 已指向你的 conda 环境,`run_backend.sh` 里的 `$SOD_HOME/env/bin/uvicorn` 就是你环境里的 uvicorn,
>   **照常用 `run_backend.sh` 即可,不用手动敲 uvicorn 命令**(裸跑会丢掉离线变量/字体/工作目录设置)。
> - 复用会往这个 conda 环境**补装依赖**,可能影响用它的其它项目;不想污染就用 `conda create -n SOD_new --clone myenv` 克隆一份再软链,或走场景一新建独立环境。
